David Hilbert asked for a procedure that decides if a polynomial equation has a solution. For solutions in integers, the answer has been "no such procedure exists" since 1970. OpenAI reports the same answer for solutions in fractions.

{{facts}}

The question

A Diophantine equation is a polynomial equation with integer coefficients, such as \(x^2 + y^2 = 3\). In 1900, Hilbert asked for a general process that accepts any such equation. In a finite number of steps, it must decide if the equation has a solution in integers. This was the tenth problem on his list.

The same question applies to other number systems. The result on this page asks about solutions in the rational numbers \(\mathbb{Q}\), which are the fractions.

An algorithm here means one fixed program. It must accept every equation as input. It must always stop, and it must then give the correct answer. A problem with no such program is undecidable.

To find a solution, a program can search. It lists all fractions by size and tests them in the equation. If a solution exists, the search finds it after finitely many tests.

The search has two limits. First, a solution can be enormous. The equation \(y^2 = x^3 + 877x\) has the trivial solution \(x = y = 0\). Its simplest other solution, which Bremner and Cassels gave in 1984, has this value of \(x\):

\[ x = \frac{375494528127162193105504069942092792346201}{6215987776871505425463220780697238044100} \]

Second, a search can never answer "no". If an equation has no solution, the search continues without end. A "no" answer needs an argument.

For \(x^2 + y^2 = 3\), this argument works. A rational solution gives integers with \(a^2 + b^2 = 3c^2\) and no common factor. Squares leave remainder 0 or 1 when divided by 3. So 3 must divide both \(a\) and \(b\). Then 3 also divides \(c\), which contradicts "no common factor".

That argument works for one equation. Hilbert's question asks for one method that works for all equations.

The answer for integers

Alan Turing proved in 1936 that no algorithm decides if a program stops. This is the halting problem.

Martin Davis, Hilary Putnam and Julia Robinson did the main work of 1961, and Yuri Matiyasevich completed it in 1970. Their theorem says that polynomial equations can encode programs. For each program, there is a polynomial equation that has an integer solution exactly when the program stops.

So an algorithm for integer equations would solve the halting problem, and no such algorithm exists.

This argument does not transfer directly to fractions. The direct route needs a polynomial test for "this fraction is an integer". That test is the subject of a separate page, \(\mathbb{Z}\) is Diophantine in \(\mathbb{Q}\), and a conjecture of Barry Mazur made it appear unlikely.

{{divider}}

The result

The OpenAI preprint states this theorem. The number of variables is part of the input.

No algorithm decides, for every polynomial \(f\) with integer coefficients, if \(f\) has a zero in \(\mathbb{Q}^n\).

The preprint gives two stronger forms of this statement. Each keeps the same difficulty as the halting problem.

  • The problem stays undecidable for polynomials of total degree at most 4, with any number of variables.
  • The problem stays undecidable for a sum of squares of polynomials of degree at most 2.

The preprint does not build a polynomial test for integers. Its route differs from the route for integers. A follow-up by Zhi-Wei Sun states that the problem stays undecidable with at most 86 unknowns.

What the result does not say

  • It does not say that a single equation is impossible to solve. Each equation has a definite answer. The result says that no single program gets all equations right.
  • It does not end the study of special families. Algorithms exist for equations of degree 1 and for one equation of degree 2. Hasse and Minkowski's theorem gives the degree 2 case.
  • It does not cover degree 3. The preprint's limit is degree 4. Equations such as \(y^2 = x^3 + 877x\) have degree 3, and this result does not decide them.
  • It does not supply a practical method or a limit on a known computer. It concerns what any program can do, with unlimited time and memory.

Why the result matters

The integer case was closed in 1970, and the rational case stayed open for decades. Many central questions in number theory ask for rational solutions, for example on elliptic curves. So the rational case is close to many working questions of the field.

The strategy also surprised specialists. Hector Pasten told Scientific American that the proof connects two of his ideas from different areas, and that the connection surprised him.

How far the result has been checked

OpenAI released the preprint on 6 October 2026, as raw output of an internal model. It has no Lean proof in OpenAI's status list. OpenAI warns that results without a Lean proof can contain errors.

Two later works use the preprint: Sun's paper on 86 unknowns and Glazer's manuscript on the integers. Use of a preprint is not the same as a check of it. A search on 5 November 2026 found no published independent check of the argument. Read the theorem on this page as a report, not as an established result.
