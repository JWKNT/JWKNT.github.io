All-Pairs Shortest Paths

All-pairs shortest paths asks for the shortest route between every pair of vertices in a weighted directed graph. With n vertices, the textbook method tries each vertex as a stop between each pair, which takes about n3 steps. Decades of work saved less than any fixed power of n.

The problem is a matrix product with different operations. Replace addition with the minimum, and multiplication with addition:

(A⋆B)[i,j]=mink⁡(A[i,k]+B[k,j])

If A holds the edge weights, then A⋆A holds the shortest routes with at most two edges. Repeating this gives all the distances. So a fast product would solve the problem.

Ordinary matrix products have fast algorithms, which use subtraction to cancel terms. The minimum has no such inverse. A program that uses only minimum and addition needs about n3 operations, so any speedup must use other arithmetic.

The APSP hypothesis says that no algorithm takes n3−ε steps, for any fixed ε>0. Many other problems are equivalent to this one, such as finding a triangle of negative total weight. All of them get faster, or none of them do.

Josh Alman and Virginia Vassilevska Williams report that the hypothesis is false. Their algorithm takes n2.9995 steps, for integer weights no larger than a fixed power of n. Claude discovered the algorithm, which also gives subquadratic 3SUM. The hidden constants are enormous, so the change is in the theory.
